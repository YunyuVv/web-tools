# 流量监控方案（Cloudflare Web Analytics）

> 创建时间：2026-07-30
> 适用：web-tools（DevToolBox）纯静态导出站点，Cloudflare Pages 部署

---

## 1. 为什么用 JS 埋点式 Analytics

本项目是**纯静态导出**（`output: 'export'`，见 `next.config.ts`），无服务端、无数据库。访问量统计只能依靠**前端 JS 埋点**：在 `<head>` 注入第三方脚本，由访客浏览器上报事件。

> 关键澄清：本站在**搜索引擎视角**是标准 SSG——每个工具页在 build 时就生成独立静态 HTML（`out/tools/json-formatter/index.html` 等），SEO 完全友好。所谓"客户端路由"只影响用户在站内点链接跳转的 UX，与收录无关（见 `02-SEO与推广运营方案.md`）。埋点要处理的正是"站内跳转统计"这一小缺口。

## 2. 选型：Cloudflare Web Analytics

| 维度 | 说明 |
|---|---|
| 费用 | **永久免费（Free 计划内置）** |
| 流量上限 | **无限制**，不按 pageview 计费 |
| 隐私 | 不使用 Cookie、不收集个人数据、无需合规横幅（GDPR 友好） |
| 体积 | beacon 脚本 < 1KB，对性能几乎无影响 |
| 指标 | PV、UV、热门页面、流量来源、国家/地区、Core Web Vitals（LCP 等） |
| SPA 支持 | 支持 `spa:true` 捕获前端路由变化 |

**为什么不用其他**：
- Plausible / Umami：需付费或自托管一台服务器；
- Google Analytics：偏重，且需额外处理隐私合规；
- 这些对本站基础监控都过重。CF Web Analytics 与现有 Cloudflare Pages 部署天然一体，零额外成本。

## 3. 代码落地位置

| 文件 | 作用 |
|---|---|
| `app/layout.tsx`（第 78–96 行） | 根布局 `<head>` 内注入 CF beacon 脚本 |
| 环境变量 `NEXT_PUBLIC_CF_BEACON_TOKEN` | 注入 token（构建时内联进 HTML） |

核心代码（layout.tsx）：

```tsx
{process.env.NEXT_PUBLIC_CF_BEACON_TOKEN ? (
  <script
    id="cf-web-analytics"
    defer
    src="https://static.cloudflareinsights.com/beacon.min.js"
    data-cf-beacon={JSON.stringify({
      token: process.env.NEXT_PUBLIC_CF_BEACON_TOKEN,
      spa: true,
    })}
  />
) : null}
```

### 两个关键设计点

1. **`spa: true`**：本站工具页之间跳转是客户端路由（不整页刷新）。默认 beacon 只统计首屏，会漏记站内跳转。`spa: true` 让 CF 自动捕获前端路由变化，统计才完整——这是本站接入 analytics 的**唯一注意点**。
2. **条件渲染**：`NEXT_PUBLIC_` 变量在 **build 时**内联进 HTML。未配置 token 时整段不渲染，避免加载空 token 报错。因此**改环境变量后必须重新构建**，单纯重启无效。

> 范式备注：脚本以裸 `<script>` 放在根 `<head>`，导出构建下保留为绘制前同步执行（已验证不会被序列化为 `self.__next_s.push` 延迟到注水）。

## 6. 数据看板与运营用法

| 指标 | 运营意义 |
|---|---|
| 热门页面 | 识别最受欢迎工具 → 优先打磨、做内容、置顶推荐 |
| 流量来源 | 区分搜索 / 直接 / 社交 / 引荐 → 判断哪个推广渠道有效 |
| 国家/地区 | 判断主力市场，指导多语言优先级 |
| Core Web Vitals | 监控性能，避免工具页卡顿影响留存 |

## 7. 免费边界与备选

- 免费版是**页面级指标**：能看"哪个工具被看多少次、从哪来"，但无转化漏斗、会话回放、用户级路径。
- 自定义事件（如"点击某按钮"）需走 beacon API 手动上报，基础 PV/UV 不需要。
- 若将来需要更细维度，可加 `components/AnalyticsTracker.tsx`（Client Component + `usePathname()`）做按工具细分上报——当前 JSON-LD + 热门页面已能提供工具粒度数据，优先级不高。
