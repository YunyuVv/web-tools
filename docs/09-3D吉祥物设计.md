# 3D 吉祥物设计文档（可把玩的趣味元素）

> 创建时间：2026-07-31  
> 适用范围：`components/three/*`、`app/[locale]/demo/3d-mascot/*`、`components/home/ToolsHomePage.tsx`、首页 Hero 集成  
> 目标：在不破坏「克制而现代化、工具页首屏直接给功能」基调的前提下，给本站增加一个**可拖拽旋转、有 idle 微动**的 3D 品牌吉祥物，提升首屏趣味性与品牌记忆点。

---

## 1. 目标与定位

| 维度 | 决策 |
|---|---|
| 形态 | 可把玩的 3D 吉祥物（程序化生成的可爱几何体角色，非外部 GLB 资源起步） |
| 位置 | 首页 Hero 区（desktop 两栏：左=文案+搜索，右=吉祥物；mobile 降级为小尺寸、不抢搜索） |
| 交互 | 鼠标/触摸**拖拽旋转** + 离开后**缓慢 idle 自转** + hover/点击有**反馈微动**（眨眼/挥手/弹跳） |
| 调性 | 克制：吉祥物是「点睛」而非「主角」，搜索仍是首屏核心；配色走品牌青绿 + 深浅自适应 |
| 约束 | 纯客户端渲染（站点 `output:'export'` 静态导出）；尊重 `prefers-reduced-motion`；无 WebGL 时静态降级 |

> 与项目风格的兼容性：本站立项原则是「减少装饰、直接给功能」。吉祥物**只放在首页 Hero**，不进工具页；Hero 仍是搜索优先布局，吉祥物在 desktop 占据右侧补充位、mobile 缩到次要位置。这是对「克制」基调的尊重，而非破坏。

### 1.1 实施策略：先做独立 Demo 测试页（不碰首页源码）

- **第一阶段（当前）**：新建**独立 demo 路由** `app/[locale]/demo/3d-mascot/` 作为 3D 吉祥物的**完整原型与测试沙盒**。模型、场景、交互、主题、无障碍、性能、i18n **全部先在这页做并验证**，首页 `ToolsHomePage` 源码**暂不动**。
- **第二阶段（demo 稳定后）**：再把验证过的 `MascotCanvas` 集成进首页 Hero（即原第七步），届时首页才会出现吉祥物。
- **理由**：首页有 SEO/AdSense/LCP 约束，直接改风险高；独立 demo 可自由试错、互不污染，验证通过后再下沉到生产页，回滚也干净（删 demo 路由即可）。
- **Demo 访问路径**：构建后访问 `/zh-CN/demo/3d-mascot`、`/zh-TW/demo/3d-mascot` 等带前缀地址（demo 目前只挂在 `[locale]` 路由下，无前缀英文版不暴露 demo，符合现有 `demo/segmented` 的约定）。本地 `npm run dev` 后可直接打开对应路径。

## 2. 概念设计（吉祥物设定）

**已确认建模方式（方案 B）：最终模型用 Blender 建模导出 GLB，但开发/验证阶段先用「程序化占位模型」把整套 3D 管线跑通**。理由：我方无法直接生成 `.glb`，而 demo 页要验证的是「R3F 渲染 + 拖拽/idle/挥手 + 主题换色 + WebGL/reduced-motion 降级 + 静态导出构建」这些与具体造型无关的能力；占位模型只是临时替身，你用 Blender 出图后一行 `useGLTF` 替换即可，交互层零改动。

- **开发期（当前）**：`components/three/MascotModel.tsx` 用 three.js 基础几何体（圆角盒/球/胶囊）拼一个极简占位角色，仅用于验证管线。
- **最终（你提供 GLB）**：Blender 建模 → 导出 `public/models/tooly.glb`（自托管）→ drei `useGLTF('/models/tooly.glb')` 替换 `MascotModel`，详见第 10 节。

建议设定（可在实现前微调草图）：

- **名字**：`Tooly`（英文）/ `工具仔`（简中）/ `工具仔`（繁中）—— 三语言键 `home.mascot.name`。
- **造型**：圆润的「小方块脑袋 + 大眼睛 + 一对小手」的极简机器人/工具箱精灵。
  - 头/身：圆角立方体（`RoundedBox`，drei 提供）或 `BoxGeometry` + 倒角。
  - 眼睛：两个白色球体 + 深色瞳孔，可做「眨眼」（缩放 y 轴）。
  - 手：两个小球或胶囊，做「挥手」（绕肩旋转）。
  - 头顶/胸口：一个工具图标暗示（如扳手/齿轮，用 `ExtrudeGeometry` 或简单圆环+矩形拼）。
- **配色**：主体用品牌 `primary` 青绿（浅色更亮、深色更沉），眼睛/高光白，瞳孔深灰；材质用 `meshStandardMaterial`（受光更立体）或 `meshPhysicalMaterial`（轻微透感）。
- **比例/尺寸**：在 Canvas 内居中，相机 `fov≈35`，模型约占视口 60%，保证留白。

> **Blender→GLB 替换是机械操作**：占位几何体与 GLB 都实现同一个「可旋转组 + 暴露 refs（眼睛/手）」接口，换模型时只改 `MascotModel.tsx` 内部，外层 `Mascot`/`MascotCanvas` 不动。

## 3. 技术选型与约束

### 3.1 为什么用 R3F（而非裸 three.js）

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| `@react-three/fiber` + `@react-three/drei` | React 声明式、组件化，与本站 React 19/Next 16 天然契合；drei 提供 `OrbitControls`/`RoundedBox`/`Environment`/`useGLTF` 等现成件，代码量小、可维护 | 引入 three.js + R3F + drei 体积较大 | **推荐**：3D 本就必须有引擎，R3F 是 React 项目最省心的封装 |
| 裸 `three.js` 手写 | 体积最小、可控 | 命令式代码量大、与 React 生命周期/卸载清理易出 bug | 备选：若构建体积超标再回退 |

> **对「零依赖」基调的说明**：项目刻意不装 framer-motion 是为了「少一个动画大依赖」。但 3D 必须有真实引擎，无法用 CSS 替代；R3F 是业界标准且 React 友好。我们用**代码分割 + 懒挂载 + 仅首页加载**把体积影响压到最低（见第 6 节），属合理例外。

### 3.2 版本与兼容性（重要）

- `@react-three/fiber` **v9** 才支持 React 19；本站 React `19.2.4`，务必装 v9+。
- `@react-three/drei` 装与 R3F v9 匹配的较新版本。
- `three` 与 `@types/three` 版本对齐。
- 安装命令（在本地验证，勿自动 push）：
  ```bash
  npm install three @react-three/fiber@^9 @react-three/drei @types/three
  ```

### 3.3 静态导出（output:'export'）专属注意

- **3D 必须客户端渲染**。用 `next/dynamic(..., { ssr: false })` 懒加载 Canvas 组件。
- ⚠️ **App Router 坑**：`ssr:false` 的 `next/dynamic` **只能在 Client Component 里调用**。当前 `ToolsHomePage` 是 Server Component（被 `page.tsx` 的 async server 渲染）。因此必须新建一个 `'use client'` 的包装组件（如 `MascotCanvas.tsx`）来承载 `dynamic(... ssr:false)`，再由 Server 的 `ToolsHomePage` 引入它。
- **Turbopack 构建**：three.js 是纯 JS（无 wasm），不像 jSquash 那样会被 Turbopack 打包卡死；正常 `npm run build` 即可。仍建议第 1 步先 spike 验证一次。
- 字体无影响（不涉及 `next/font/google`）。

### 3.4 性能 / SEO / 广告

- 首页有 SEO 与 AdSense，**LCP 不能退化**：Hero 文案+搜索走 SSR 首帧直出；3D Canvas 在 hydration 后 `dynamic` 注入，**不进首屏 HTML、不阻塞 LCP**。
- `Canvas` 设 `dpr={[1, 2]}` 限制像素比；`frameloop` 用 `"demand"`（仅交互/动画时渲染）或 idle 时用低帧；离开视口用 `IntersectionObserver` 暂停渲染。
- 组件卸载时 R3F 自动 dispose；确保不泄漏 GPU 资源。

### 3.5 无障碍与降级

- 无 WebGL / 不支持 → 显示**静态 fallback**（现有 `DotField` 海报感背景 或 一张吉祥物 PNG 海报），保证无 3D 也有体面首屏。
- `prefers-reduced-motion: reduce` → **关闭 idle 自转与弹跳**，仅保留静态或可手动拖拽。
- 吉祥物容器 `role="img"` + `aria-label={t('home.mascot.name')}` 描述；若视为纯装饰则 `aria-hidden`，但因其可交互，建议给可访问名 + 一句话说明「可拖拽旋转」。
- 键盘：至少给一个「随机转一下」按钮（可选），保证非指针用户也能玩。

## 4. 分步实施计划

> 每步都给出：目标 / 动作 / 涉及文件 / 验收。第 2–6 步（建模/场景/交互/主题/性能）**均在独立 demo 页内实现并验证**，不触碰首页源码；首页集成延后到第二阶段（第七步）。

### 第一步：独立 Demo 测试页（全功能原型 + 去风险）

- **目标**：在独立路由里把吉祥物**完整跑起来并验证**（不只是最小方块），同时证明静态导出 + Turbopack + R3F 可行。首页源码本步不动。
- **动作**：
  1. 装依赖（见 3.2）。
  2. 新建 demo 路由 `app/[locale]/demo/3d-mascot/page.tsx`（参考 `app/[locale]/demo/segmented`），作为测试沙盒页（含标题、操作提示、主题切换入口、reduced-motion 说明）。
  3. 落地 `components/three/` 三件套：`MascotCanvas.tsx`（Client 包装 + `dynamic(ssr:false)` + WebGL/reduced-motion 降级 + i18n aria）、`Mascot.tsx`（场景/灯光/交互）、`MascotModel.tsx`（程序化角色）。
  4. 在 demo 页引入 `MascotCanvas`，跑 `NODE_OPTIONS= npm run build` 确认导出 `out/` 无报错、three.js chunk 被正确 code-split（不进首屏 HTML）。
- **涉及文件**：`app/[locale]/demo/3d-mascot/page.tsx`、`components/three/MascotCanvas.tsx`、`Mascot.tsx`、`MascotModel.tsx`。
- **验收**：构建通过；demo 页能看到可旋转的程序化吉祥物；记录 Turbopack 是否需特殊处理；确认 demo 页未改动 `ToolsHomePage` 等首页源码。

### 第二步：占位程序化模型（验证用，非最终造型）

- **目标**：用 three.js 基础几何体拼一个**临时占位**角色，仅用于在 demo 页验证管线与交互；最终造型由你的 Blender GLB 决定（见第十步）。
- **动作**：
  1. 在 `components/three/MascotModel.tsx` 用 `<group>` 组织：身体 `RoundedBox`、眼睛（两球+瞳孔）、手（胶囊）、头顶工具符号。
  2. 定义部件 ref（眼睛组、左手组）供后续动画。
  3. 材质走 `meshStandardMaterial`，颜色用品牌青绿（从 CSS 变量或常量取，见 3.4 主题同步）。
- **涉及文件**：`components/three/MascotModel.tsx`。
- **验收**：Canvas 中渲染出可辨认的可爱角色，明暗主题下都好看。

### 第三步：场景与灯光

- **目标**：搭建相机、灯光、背景，使角色立体且不突兀。
- **动作**：
  1. `<Canvas camera={{ fov:35, position:[0,0,5] }} dpr={[1,2]} gl={{ alpha:true }}>` —— `alpha:true` 让背景透明，透出页面底色/`DotField`。
  2. 灯光：`<ambientLight intensity={0.6}/>` + `<directionalLight position={[3,5,4]} intensity={1.2}/>`；可选 `<Environment preset="city"/>`（drei，注意它会 fetch HDRI，静态站可能需自托管——**先不用，避免外部请求**，用手动灯光即可）。
  3. 不用地面阴影（`ContactShadows` 也先不引），保持轻量。
- **涉及文件**：`components/three/Mascot.tsx`（场景容器）。
- **验收**：角色受光自然、边缘不过曝；背景透明融入 Hero。

### 第四步：交互（拖拽 + idle + 反馈）

- **目标**：实现「可把玩」。
- **动作**：
  1. **拖拽旋转**：用 drei `<OrbitControls enableZoom={false} enablePan={false} autoRotate={false}/>`，或手写 pointer 事件旋转 `<group>`（更可控、体积更小）。推荐手写 `onPointerDown/Move/Up` 改 group 的 `rotation.y/x`，限制俯仰角。
  2. **idle 自转**：用 `useFrame` 在没有拖拽时缓慢 `rotation.y += delta*0.3`。
  3. **反馈微动**：hover 时眼睛放大/身体轻微缩放；点击时「挥手」（左手组绕轴转一圈）+ 轻微弹跳（`position.y` 正弦）。
  4. **触摸**：pointer 事件天然覆盖触摸；`touch-action: none` 防页面滚动冲突。
- **涉及文件**：`components/three/Mascot.tsx`、`MascotModel.tsx`。
- **验收**：桌面拖拽顺滑、松手缓慢自转；点击有挥手/弹跳；移动端可单指旋转且不触发页面滚动。

### 第五步：主题与无障碍

- **目标**：深浅主题自适应 + 降级。
- **动作**：
  1. 用 `next-themes` 的 `useTheme()` 读 `resolvedTheme`，切换材质颜色/灯光强度（深色更沉、浅色更亮）。
  2. `prefers-reduced-motion`：用 `window.matchMedia('(prefers-reduced-motion: reduce)')` 或 CSS 媒体查询标志，**关闭 idle 自转与弹跳**，仅允许手动拖拽。
  3. WebGL 检测：挂载前 `try { document.createElement('canvas').getContext('webgl') }`，不支持则渲染 fallback（`<DotField/>` 或 PNG 海报）。
  4. 容器 `role="img"` + `aria-label`。
- **涉及文件**：`components/three/MascotCanvas.tsx`（Client 包装，含检测/fallback/dynamic）。
- **验收**：切深色主题材质跟随；系统开启减少动效后无自动旋转；无 WebGL 设备显示静态海报。

### 第六步：性能优化

- **目标**：保证 LCP/包体可控。
- **动作**：
  1. `MascotCanvas` 内 `dynamic(() => import('./Mascot'), { ssr:false, loading: () => <DotField/> })`。
  2. `frameloop="demand"` + 交互时临时切 `"always"`，或用 `invalidate()` 控制；idle 自转时低频渲染。
  3. `IntersectionObserver` 监听容器，离屏 `frameloop="never"`。
  4. 限制 `dpr={[1,2]}`。
- **涉及文件**：`components/three/MascotCanvas.tsx`、`Mascot.tsx`。
- **验收**：首页首屏 HTML 不含 three.js chunk；Lighthouse 移动端 LCP 无显著退化（对比接入前后）。

### 第七步（第二阶段，demo 验证通过后再做）：首页 Hero 集成

- **状态**：⏸ **本阶段不做**。等第一步的 demo 页在模型/交互/主题/性能/i18n 全部验证稳定后，再下沉到首页。
- **目标**：把吉祥物放进首页，保持搜索优先。
- **动作**（延后执行）：

     - 左列：现有 `h1` + `subtitle` + `HomeSearch`（搜索优先，不动）。
     - 右列：`MascotCanvas`（限定高度，如 `h-[320px] sm:h-[420px]`）。

- **目标**：固化规范、本地构建、预览验证。
- **动作**：
  1. 本文档即规范，补齐「涉及文件」实际路径。
  2. 本地 `NODE_OPTIONS= npm run build` 通过；`npm run dev` 手测拖拽/主题/reduced-motion/无 WebGL fallback。

  4. Lighthouse 移动端跑一次，确认 LCP/CLS 无退化。
- **验收**：构建绿、手测通过、预览无回归。

### 第十步（最终模型，必做）：Blender 建模 → GLB 替换

- **目标**：用 Blender（免费开源）做出精致角色，替换占位几何体，得到最终吉祥物外观。
- **Blender 建模建议**：
  - 低多边形、四边面为主；节点**命名规范**（如 `body` / `eye.L` / `eye.R` / `hand.L` / `hand.R`），方便代码按名取 ref 做眨眼/挥手。
  - 颜色先用中性灰，主题换色在代码里覆盖材质（见下），无需在 Blender 里定死品牌色。
- **导出设置**：glTF 2.0 Binary（`.glb`）；确认「+Y Up」；面数偏高时勾选 **Draco 压缩**（drei `useGLTF` 支持，decoder 需自托管到 `public/draco/` 以避免外部 CDN 请求，契合静态站）。
- **自托管与加载**：把 `tooly.glb` 放 `public/models/`，导出构建自动拷入 `out/`；代码中 `const { scene } = useGLTF('/models/tooly.glb')`，用 `<primitive object={scene} />` 渲染；遍历节点把 `meshStandardMaterial.color` 覆写为品牌青绿，深浅主题切换时改 `intensity`/颜色，保持与占位期一致的换色逻辑。
- **动画衔接**：若在 Blender 做了挥手/眨眼骨骼动画，用 drei `useAnimations` 播放；否则沿用代码里的程序化微动（绕手 ref 旋转、缩放眼）即可。
- **关键**：拖拽/idle/反馈这套交互层写在 `Mascot`/`MascotCanvas`，与 `MascotModel` 内部造型解耦——换 GLB **只改 `MascotModel.tsx` 一个文件**，交互零改动。

> **完整落地手册（安装 Blender + 让 AI 辅助建模 + 导出并接入）见 `docs/11-Blender建模GLB方案.md`**：含官网下载地址（Apple Silicon / Intel 选包）、Blender MCP 实时联动配置、bpy 脚本 headless 导出示例、Draco 优化与接入代码。

import { Canvas, useFrame } from '@react-three/fiber'
import { RoundedBox } from '@react-three/drei'
import { useRef } from 'react'
import { MascotModel } from './MascotModel'

export default function Mascot() {
  const group = useRef<any>(null)
  const dragging = useRef(false)
  useFrame((_, delta) => {

  })
  return (

      <directionalLight position={[3, 5, 4]} intensity={1.2} />
      <group
        ref={group}
        onPointerDown={() => (dragging.current = true)}
        onPointerUp={() => (dragging.current = false)}

## 8. 风险与回滚

| 风险 | 触发 | 缓解 / 回滚 |
|---|---|---|
| 构建体积超标 | R3F+drei 大 | 代码分割+懒挂载已控；仍超标则回退裸 three.js 或精简 drei 引用（只引用到的子模块） |
| 首页 LCP 退化（影响 SEO/广告） | 3D 进首屏 | 已用 `ssr:false`+`dynamic` 隔离；若退化，降级为 `loading` 静态海报常驻、Canvas 延迟到 `requestIdleCallback` 挂载 |
| Turbopack 构建卡死 | 误打包 wasm | three.js 无 wasm，已避开 jSquash 类坑；spike（第一步）提前验证 |
| `ssr:false` 在 Server Component 报错 | App Router 限制 | 已规划 Client 包装组件 `MascotCanvas` 承载 dynamic |
| WebGL 不支持 | 旧设备/无 GPU | 静态 fallback（DotField/PNG）已设计 |
| 视觉喧宾夺主 | 破坏「克制」基调 | 仅首页 Hero、desktop 右侧补充位、mobile 降级；可调小尺寸/降透明度 |
